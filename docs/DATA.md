## 2. 품질 좋은 데이터 만드는 방법

효과 대비 비용 순. "손코딩 엔진 말고" 정보원이 다른 것은 ★.

### 기반 (먼저 해야 다른 방법이 의미 있음)
- **기록기 고치기**: 자가대국이 국면마다 전체 상태(전역 필드 포함)와 규칙 버전(사이트 번들 해시)을 저장. 이후 모든 데이터가 A등급이 되어 재분석, 반복 정답 갱신이 가능해짐.
- **위생 규칙**: `unfinished`/`explorationTainted` 제외, 같은 국면 중복 제거(새 국면 키 기준), 한 판에서 뽑는 국면 수 상한(상관 줄이기), 규칙 버전이 다르면 섞지 않음, 학습/검증은 국면이 아니라 판 단위로 나눔.

### 정답 품질
1. **여러 번 이어 두기(롤아웃 평균) 정답**: 한 국면에서 무작위 시드를 바꿔 N판(예: 8~16) 이어 두고 결과 평균을 정답으로. 대국 하나의 운과 무승부 잡음이 N배 줄어듦. 클라우드에서 병렬로 쉬움. 이어 두는 엔진은 핸드코딩이어도 되지만 정답의 잡음 구조가 달라짐.
2. **깊은 재분석**: 지금 도구(`tools/reanalyze`)로 깊이 3 이상 PV 끝 평가. 국면 키 수정과 전치표 최선 수 저장으로 같은 시간에 더 깊이 가능. 단 평가가 핸드코딩이면 핸드코딩의 깊은 판단을 배우는 것.
3. ★ **몬테카를로 트리 탐색 자가대국**(`tools/mcts/`가 이미 있음): 방문 수 분포를 정책 정답으로, 트리 평균값을 가치 정답으로. 평가 함수가 아니라 실제 결과에서 값이 나오므로 핸드코딩 평가에서 벗어남. 무작위/카드 연속 사용과도 잘 맞음. 비용이 큼.
4. ★ **사이트 AI 대국**: 로컬에 있는 사이트 실제 워커(`real-worker.js`, 빠른 버전 3.7배)로 사이트 AI끼리, 또는 사이트 AI 대 우리 엔진. 규칙이 정답 그대로라는 장점. 다만 우리 엔진의 원본이라 판단은 비슷할 가능성이 큼(대국 결과의 차이는 규칙 차이 쪽).
5. ★ **사람 기보**: 사이트 실제 대국 기록. 가장 다른 정보원이지만 운영자 동의 증빙(NOTICE.md 인용)이 먼저 필요. 사람 실력 편차가 커서 높은 등급 플레이어만 쓰는 필터가 필요.

### 국면 다양성
6. **시작 다양화**: 사이트식 덱 배분(`SELFPLAY_SITE_DRAFT`), 핸디캡 시작(무승부 감소), 실제 중반 국면에서 출발하는 짧은 대국.
7. **약점 국면 채굴**: 대전에서 진 판의 결정적 국면(평가가 크게 뒤집힌 지점)을 모아 그 주변을 집중 재분석.
8. ★ **전술 문제 생성**: 깊은 탐색으로 "유일하게 이기는 수"가 있는 국면을 자동 수집 → 정책 정답 + 측정용 문제집(대국 없이 평가 비교 가능).

### 다양한 상대 (자가대국 피드백 위험 대비)
9. **리그 자가대국**: 핸드코딩, 평가 0, 옛 모델, 깊이 다른 설정이 섞여 둠. 같은 엔진끼리만 두면 무승부율이 오르고(40.8% → 52.7%, ExperimentNote 8번) 한쪽 버릇만 학습함.

### 추천하지 않는 것
- **언어 모델로 국면 판정**: 규칙이 너무 특수해 정답 품질을 보장할 수 없고 검증 수단도 없음.
- **탐색 루트 점수(`searchScore`)를 정답으로 계속 섞기**: 단위가 다른 경로 합(부호 반대 20%).

## 3. 추천 순서
1. 기록기 고치기 + 위생 규칙 (코드 작음, 모든 다음 단계의 전제)
2. 롤아웃 평균 정답 시험판: 재분석과 같은 2만 국면에 붙여 (a) 결과만 / (b) 롤아웃 평균으로 학습 비교. 판정은 순수 탐색 모드가 생긴 뒤 대전으로(지금 엔진은 평가 차이를 재지 못함).
3. 전술 문제집: 평가 품질을 대국 없이 재는 측정 도구로도 쓰임.
4. 몬테카를로 트리 자가대국: 탐색 방향(갈래 2)을 고르면 그때.
5. 사람 기보: 운영자 동의 증빙이 저장되면.
