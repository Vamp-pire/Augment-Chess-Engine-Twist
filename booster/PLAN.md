## 스톡피시 섞기 (보류, 저장만)
- **일반 국면 보조**: Fairy-Stockfish(표준 체스 + `stalemateValue = loss`)를 확장 오프스크린 문서에서 WASM으로 실행. 문 조건: 표준 기물만, 시한 효과/규칙 카드/특수승리 없음, 8x8. 상위 3수(MultiPV)를 부스터의 실제 규칙 검증(상대 응수, 상대 카드)에 넣고, 실패하면 부스터 엔진 수.
- **카드 국면 보조**: (1) 이동형 카드 기물을 Betza 표기로 정의, (2) 시한 효과가 끝난 뒤 국면 장기 평가, (3) 카드 적용 후 국면 평가(쓴 경우 대 안 쓴 경우), (4) 모르는 기물을 가까운 표준 기물로 바꾼 판은 후보 정렬에만.
- 비중: 일반 국면 주도 > Betza 정의 가능 > 만료 뒤/카드 적용 뒤 보조 > 근사 판은 정렬만. 최종 선택은 항상 실제 규칙 검증 통과.
- 먼저 잴 것: 실제 대국에서 일반 국면 비율. 걸림돌: 사이트 CSP(워커 안 WASM), GPL(개인용은 문제없음).

## 드래프트 AI

### 자료 조사 결과
- **사이트 드래프트 AI**(`main.js`, 모듈 내부): 점수 = 별 x 2 + 기물 카드 0.8 + 효과별 고정 가산점(약 30종) + 판 상황 가산점(카드별 규칙) + 패시브 0.7, 상위 2.8점 안에서 온도 1.1 무작위 추첨(`pickAiDraftVariety`). 일반/울트라가 같은 추첨 함수를 씀. 그랜드(`pickAiGrandDraftCard`), 카오스(`pickAiDraftBundle`)는 별도.
- **디스코드 "증강별 시너지/카운터 증강 메모장"**(VCA 서버 증강체스-잡담 스레드, 294개 글, 11/22~): 카드 제목 255개 중 내용이 있는 것 55개, 시너지 약 63항목, 카운터 약 42항목, 이유 설명 포함(예: 호드+몽골리안 갬빗, 프린세스+퀸 희생 카드, 오목/하이랜더 조합). 주로 한 사람이 작성, 측정이 아닌 의견. **쓸모: 시너지 그래프의 초기값(사전 지식)**, 시뮬레이션으로 검증해서 가중치를 정함.
- 같은 채널에서 다른 사람도 사이트 AI를 만들고 있고 "카드 뽑기 개선은 2.0.0", "조합을 직접 AI에 떠먹여야"라고 함. 방향이 같음.
- **카드통계 확장의 Supabase 집계**(`get_card_stats`): 지금 빈 결과(사람 대국 데이터 없음).
- 접근 권한 없는 스레드: "증강체스 오프닝 정리" 등(봇 403).

### 게임에 끼워 넣기
- 페이지(MAIN world)에서 `Array.prototype.filter`를 감싸, `{card, score}` 모양 배열이 들어오면(드래프트 추첨 직전) 우리 AI가 고른 카드 점수만 크게, 나머지는 낮게 바꿈 → 사이트 AI가 무작위 없이 우리 선택을 고름. 본체 교체 없음, CSP 그대로.
- 판 정보: 부스터가 가로채는 AI 요청의 마지막 국면(`snapshot`)과 손패.
- 그랜드/카오스는 함수 모양 확인 후 같은 방식 또는 별도 처리.

### 만드는 방법 후보 (저장)
| 방법 | 내용 | 비용 | 강점 / 약점 |
|---|---|---|---|
| A. 규칙 + 시너지 그래프 | 사이트 점수 + 엔진이 이해하는 카드 가산(부스터가 시한 효과/특수승리를 계산하는 카드) + 디스코드 시너지/카운터 그래프(손패, 상대 손패) | 작음 | 바로 가능 / 의견 기반 |
| B. 시뮬레이션 카드 가치표 | Node에서 사이트 워커로 부스터 AI끼리 무작위 드래프트 대국 → 가진 카드로 승패 로지스틱 회귀(카드 가치 + 자주 나온 쌍 상호작용) | 큼(실제 규칙 대국이 느림, 클라우드 20작업) | 측정 기반, 우리 엔진이 잘 쓰는 카드를 반영 / 데이터가 많이 필요 |
| C. 드래프트 순간 탐색 | 후보 카드마다 "지금 손에 있다면" 포크한 세션에 카드를 넣고 부스터의 카드 평가(`scoreAfterCard`)로 즉시 이득을 잼 | 후보당 약 0.3초 | 지금 판에 맞춤 / 나중에 쓸 가치는 못 봄 |
| D. 카드 설명 자동 분류 | 카드 목록(`card-catalogs-*.js`) 설명을 Gemini로 유형(소환/변신/제거/보호/봉쇄/규칙/특수승리)과 조건으로 태깅 → A, B의 특징으로 | 작음 | 255장 전체를 덮음 / 태깅 오류 가능, 검증 필요 |
| E. 리그 학습 | B의 가치표로 드래프트하는 AI끼리 리그를 돌려 가치를 반복 갱신(밴딧) | 큼 | 메타 변화 반영 / 가장 오래 걸림 |

추천: **A + C로 1판 → B로 가치표 → D로 빈칸 채우기 → E는 B가 안정된 뒤**. 최종 점수 = 가치표(B) + 시너지(A, 학습된 가중치) + 즉시 이득(C) + 엔진 호환 가산. 비슷한 점수 안에서 약간의 무작위 유지(매번 같은 덱 방지).

## 카드 사용 개선 (보류, 저장만)

### 한 턴에 카드 여러 장 연달아 쓰기
- 지금: 카드 하나 + 같은 턴에 이어 두는 수까지만 실제 규칙으로 검증.
- 개선: 턴 안의 행동 순서(카드 -> 카드 -> 수)를 **빔 탐색**(깊이 3, 폭 4 정도)으로 실제 규칙 엔진에 적용, 끝 국면을 부스터 엔진으로 평가. 카드 적용이 느리니(40~300ms) 시너지 그래프로 같이 쓸 만한 쌍부터.

### 턴을 넘는 계획 (이번 턴 A, 다음 턴 B)
- 카드마다 **아껴 둘 가치**: 지금 쓰는 이득 대 다음 턴에 쓸 기대 이득 비교(고정 50점 기준 대체).
- 쌍 계획: A 적용 -> 엔진 주 변화(우리 수, 상대 예상 응수) 끝 국면에서 B를 쓴 점수를 재서, A+B 경로가 A 단독/B 단독보다 낫고 상대 응수에 버티면 A를 지금 씀. 후보 쌍은 손패 2~3장 + 시너지 그래프로 제한.
- 상대도 같은 방식으로: 상대 손패의 2장 연계를 위협으로 확인(지금은 1장).
